# September 2026 improvement pass

The requested items were implemented and verified one at a time. This report records the resulting behavior, ownership boundaries and validation scope.

## Changes and causes

1. **Equipment availability.** The picker previously listed owned equipment without excluding assigned pieces. `gameplay/progression/relics.gd` now derives available IDs from authoritative tower ownership. `ui/towers/relic_picker.gd` and `tower_dialog.gd` refresh and reject stale choices after equipment transfers, removal, tower changes and reopening. Unassigned pieces reappear.
2. **Creative starting gold.** Fresh sessions previously used a fixed balance. The reusable Session Level node in `content/catalogs/levels.gd` now exposes starting gold through the existing tuning schema and Developer Controls. `gameplay/game_state.gd`, `persistence/save_slots.gd` and `ui/save_slots_panel.gd` apply the selected value when creating a session, including typed values. Editing the setting does not replace an existing world's balance.
3. **Survival stat transfer.** Existing world-build exports included world state. `persistence/stat_configuration.gd` adds a separately identified, checksummed stats-only format, reused by the slot library and `ui/developer/stat_configurations.gd`. Players can create/copy/edit, save, export and import named statistics and start a fresh world in either mode. Editing a draft does not unlock or mutate an active Survival session.
4. **Settings shadows.** `ui/panels.gd` had explicit shadow styling on its settings cards. Removing those local overrides preserves the shared surface style on other screens.
5. **Campaign balancing.** `campaign/configuration.gd` derives existing Level and Wave content nodes with validated resource, gameplay-stat and spawn-group overrides. `campaign/balance_panel.gd` reuses Developer Controls and catalog field bounds. Level defaults and wave overrides are editable independently; saved changes apply on the next mission start. Authored behavior remains the default.
6. **Individual campaign exports and wave changes.** Each level can export deterministic structured data containing defaults, overrides, effective statistics, lanes, spawn schedules, health/speed/payout values and numerical changes between waves. Exports use the same effective-stat and biome calculations as gameplay, without live entities or progress.
7. **Campaign reset.** `campaign/progress.gd` adds reset through its existing archived replacement transaction. The map uses the shared confirmation popup. Reset clears the completed-level count, preserves account/world/configuration stores and removes a stale victorious run before rebuilding navigation so it cannot write completion back.
8. **Campaign selection circles.** Selection existed in both the board and screen, and screen refresh could restore an already-cleared selection. `campaign/board.gd` now owns selected sockets. The screen clears all associated targeting, dialog and move state at dismissal, removal, phase and navigation boundaries.
9. **Campaign upgrades.** A shared touch-scroll observer survived layout reparenting and changed newly created battlefield buttons from STOP to PASS. Upgrade taps then bubbled to the board and dismissed the action. `ui/shared/touch_scroll.gd` now scopes observers to their owning scroll and restores the original filter on exit. All 20 missions inherit the fix; no level-specific bypass was added.
10. **Upgrade prices.** `ui/towers/tower_actions.gd` previously revealed prices only during confirmation. Normal selection now shows the next upgrade price, including both specialization choices. Display, confirmation invalidation and purchase use the same `Balance.upgrade_cost()` result.
11. **Poison Arrow.** The former spread specialization now fires one aimed arrow with direct damage plus poison. Its Ability node composes the existing damage-over-time attribute: by default, 15 direct damage and 5 damage per second for 3 seconds. Hits from one tower refresh rather than stack; separate owners remain independent. Projectile configuration and target runtime state stay separate, and component removal/replacement, owner removal and pooling clean up effects.
12. **Ice Needle sound.** Only Frostneedle attack and impact WAVs were regenerated, replacing the high chime with lower bow textures. `tools/generate_audio.py` remains the asset source; the upgrade cue and unrelated sounds are unchanged.
13. **Repeated audio variation.** `audio/audio_director.gd` applies independent 0.9–1.1 pitch ratios to accepted shots, impacts, enemy deaths and boss footsteps. Music, UI and dramatic boss cues retain their pitch. Missing streams fail quietly. This does not consume gameplay randomness or mutate catalog/stream definitions.
14. **Account restoration.** Tokens previously existed only in memory, preventing restoration after restart. `cloud/session_store.gd` now stores a service-bound refresh credential separately from gameplay. `cloud/cloud_service.gd` verifies it with refresh on startup, persists rotation, coalesces concurrent refreshes and prevents delayed callbacks from reversing sign-out. Temporary network failures preserve retryable credentials; invalid/revoked sessions clear them. `cloud/cloud_panel.gd` exposes retry. Restoration reads account backups and never initiates an upload.

## Persistence and compatibility

- Stat codes use `hollow-vigil-stat-configuration-v1`; the payload contains exactly `version`, descriptive `setup` metadata and validated `tuning`. The `.hvstats` library contains no buildings, maps, entities, session progress or credentials. Existing `.hvbuild` decoding is preserved. Old or malformed stat codes fail validation without modifying saved configurations.
- Campaign authoring uses a separate checksummed `vigil-campaign-configuration.save` with sparse per-level/per-wave rules and recovery candidates. Campaign progress remains its independent completed-level store. Per-level exports use `hollow-vigil-campaign-level-v1`.
- Poison Arrow retains `thorn_volley` in existing saves/configurations. Retired `arrow_count` and `fan_angle` fields remain accepted but inert; editors and effective-stat reports omit them. Poison timers remain transient combat state.
- Account persistence contains only version, service URL and refresh token. Access tokens, player identity and gameplay are not persisted there. Writes use a temporary file and rename, with owner-only permissions on Unix desktops. Incomplete temporary files are never restored. Sign-out clears both files; errors are surfaced. No database migration or production account mutation was required.

## Validation

Godot 4.7.2 ran against an isolated source copy with clean imports because the shared checkout intermittently delayed filesystem reads. All 217 Godot source files were compared with the checkout after the final changes. The repository structure check and whitespace checks passed.

- Full simulation suite: **51,048 checks, zero failures**, including crowded worlds and an hour of simulated gameplay.
- Campaign reference defenses: **20/20 victories** using legal starting funds and actual earnings. Actual mouse/touch upgrade flow: **480 checks** across all 20 levels, including active waves, specialization purchases and legitimate restrictions.
- Configuration: save modes **36**, stats-only transfer **35**, campaign rules **145**, level exports **299**, campaign baseline **939**, reset **8**. Rendered configuration **27**, stat library **14**, save UI **42**, reset **6**, selection lifecycle **25**, campaign navigation **188**, price display **30**.
- Equipment/attributes: gear **840**, rendered equipment **113**, Poison Arrow **24**, branches **120**, developer tiers **2,931**. Rendered developer layout **19,452** plus input/save/reopen checks passed.
- Audio: **85 assets** validated; routing/mix **320** and playback pitch **5,553** checks passed.
- Account: session behavior **35**, cloud service **43**, manual backups **9**, campaign backups **16**, codec **41**, restore **9**, public builds **10**, and rendered account/name checks passed. A localhost HTTP fixture verified actual requests across three Godot process lifetimes: sign-in, startup refresh/token rotation, and logout/restart, with no uploads.

The audit corrected two test-fixture issues: desktop focus notifications legitimately change world save bookkeeping, so reset comparison ignores only revision/timestamp fields; rendered menu fixtures now stop and release audio before engine shutdown. An existing spawn-count assertion now respects the existing ±10% spawn interval jitter. No spawn balance was changed.

## Remaining verification limits

No known requested implementation remains unfinished. Account transport tests used synthetic/local HTTP fixtures, not a production Supabase account. Rendered touch tests ran on desktop, not a physical phone. No TestFlight build or upload was part of this pass. Audio assets and playback behavior were validated programmatically; perceived comfort should also be checked on the target device. The new poison specialization has focused correctness coverage; broader long-term balance tuning remains a separate task.
